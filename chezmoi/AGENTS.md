# chezmoi: Windows user settings

- chezmoi merges the managed defaults into Windows Terminal's stable `settings.json`, installs its color-scheme fragment and the pinned UDEV Gothic NF font, and selects Windows Terminal as the current user's default terminal.
- Keep existing Windows Terminal profiles and keybindings. Use the standard PowerShell 7 profile as default and let WSL generate its distribution profiles.
- chezmoi also manages the PowerShell 7 profile in `%USERPROFILE%/Documents/PowerShell/` for PSReadLine history prediction.
- The same profile owns Windows-native shell aliases and functions for applications declared in the WinGet manifest (`eza`, `ls`/`ll`/`la`/`lt`/`lla`, `grep`, `find`, `lg`, and `dotf`). Keep these in chezmoi; do not route them through WSL. `dotf` resolves the repository from `chezmoi source-path`. CLI install metadata remains in `windows/winget/packages.json`.
- Superfile's Windows configuration is managed in `AppData/Local/superfile/config.toml`; its hotkeys, pins, and runtime state remain application-managed.
- Setup output colors belong to `.chezmoi.toml.tmpl` (chezmoi diffs) and `dot_taskrc.yml` (Task's own output). Prefer native tool configuration over ANSI coloring in installer scripts.
- Windows Git's relative worktree links are configured in `dot_config/git/config`. Unix Git and gwq belong to Home Manager; use `task worktree:repair` for existing links.
- Windows keeps its standard desktop shortcuts outside Windows Terminal's marked WSL terminal controls. The per-user `WslSuperKey` adapter consumes Win chords there and forwards Super-modified terminal input. Do not add a Windows desktop action runtime or PowerToys dependency.
- Unix GUI applications belong to NixOS-WSL and Home Manager. Each application module in `nix/modules/` owns its package selection, settings, integrations, and dedicated runtime dependencies. Enablement, simple package lists, and single assignments belong directly in the required `nix/defaults.nix` composition. Common and OS-specific composition explicitly imports the relevant modules outside that directory. OS-specific settings, privileged operations, system services, and integration belong to the OS blocks in `nix/defaults.nix`. Existing Windows 1Password CLI/signing integration remains a host responsibility.
- Keep desktop keys in `nix/home/keybindings/bindings.nix` and Neovim keys in `nix/modules/editors/nvim/neovim.nix`. `task keybindings:export` directly evaluates the locked Nix definitions and uses jq to update committed `generated.json`. Ghostty and Herdr settings belong to their Home Manager modules. Do not duplicate key allocations in PowerShell or templates.
- Windows chezmoi deploys exported desktop and Neovim data into NixOS-WSL at `~/.config/dotfiles/keybindings/`. Home Manager owns the Neovim loader, plugins, and other Unix settings. Ghostty settings are managed directly by Home Manager on every Unix platform.
- `task install` updates and switches NixOS once in its WSL phase before applying chezmoi, so the Neovim loader is installed before the exported data. `install.cmd` bootstraps that same Task entry. Apply consumes the committed export without Nix; GHA verifies freshness rather than regenerating it.
- Run `task chezmoi` to apply the configuration.
